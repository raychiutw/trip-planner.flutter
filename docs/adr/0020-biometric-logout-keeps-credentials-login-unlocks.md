# 開啟生物辨識登入者登出時保留憑證，按「登入」直接用生物辨識解鎖

部分取代 [ADR-0019](0019-logout-revokes-biometric-login-only-while-signed-in.md) 的「登出一律撤銷並清除」。ADR-0019 其餘決定（只接受生物辨識、生物特徵變更即失效、設定頁開關只驗生物辨識、冷啟動驗一次即進「我的行程」、App 鎖不重複、重新驗證模式已移除、歡迎頁保留）照舊。

0.42.0 上線後 owner 實際使用：登出再登入要輸入帳密，與「開啟 Face ID 後登入可以選 Face ID 直接登入」的期待不符。

## Decision

- **開啟生物辨識登入者登出時保留**：不撤銷，憑證與 DPoP 金鑰留在手機上（仍只接受生物辨識）。未開啟者登出照 ADR-0019：撤銷並清除。
- **按「登入」直接解鎖**：歡迎頁有保留的憑證時，按「登入」直接跳生物辨識，通過即 refresh 並進「我的行程」；不另設按鈕、不顯示帳號名稱。
- **取消或失敗就開 web 登入頁**：生物辨識取消或失敗時開 web 登入頁輸入帳密。保留的憑證不先刪：同一帳號登入就換成新的憑證；不同帳號登入先清掉前一個人的憑證與金鑰。換 code 成功前不動保留的憑證與 DPoP 金鑰（新金鑰先只放記憶體，成功才替換），web 登入失敗時保留的憑證照舊可用。也適用於未登出、冷啟動取消生物辨識後再按「登入」的情況。
- **憑證失效開 web**：refresh 被拒（過期、被 web 撤銷）或生物特徵變更使金鑰失效時，清除並開 web 登入頁。沒開啟過生物辨識登入的人按「登入」直接開 web。
- **登出後冷啟動不自動解鎖**：主動登出後再開 App 停在歡迎頁，等使用者按「登入」；沒登出、只是關掉 App 的冷啟動照 ADR-0019 自動跳生物辨識。
- **沒有「忘記這支手機」或「使用其他帳號」入口**；登出確認框維持一般文案。
- **只改 App**：api、web 不變。

## Considered Options

- **維持 ADR-0019（登出即撤銷）**：伺服器與手機都乾淨。拒絕：owner 實際使用後要登出後仍能用 Face ID 回來。
- **歡迎頁另設「用 Face ID 登入」鈕並顯示帳號**：拒絕：owner 要按「登入」就直接解鎖。
- **「使用其他帳號」連結**：拒絕：取消生物辨識即開 web 登入頁，已能換帳號。
- **登出確認框說明伺服器端仍有效**：拒絕：owner 不要。
- **passkey**：拒絕理由同 ADR-0017／0019（後端要存憑證）。

## Consequences

- 開啟者登出後伺服器端憑證仍有效，最後一次 refresh 後 30 天失效；因綁定這支手機的 DPoP 金鑰，金鑰不在就無法使用。可從 web 已登入裝置撤銷。
- 憑證與 DPoP 金鑰回到「開啟者登出時一起保留」（同 ADR-0017），其餘情況一起刪除（[ADR-0015](0015-dpop-key-bound-tokens.md)）。
- 共用手機時，換人只要在生物辨識取消後用自己的帳號登入，前一個人的憑證會被清掉。
- Android 換帳號時，前一位使用者在 biometric 區的 refresh token 不刪（刪除會跳驗證）；其 DPoP 金鑰已被新登入取代，殘留無法使用。
- 手機上留著憑證時改用 web 登入，因硬體金鑰無法先產生不落地，這次登入改用軟體 DPoP 金鑰（ADR-0015 的後備），下次全新登入才回到硬體金鑰。
- 0.42.0 已登出的使用者沒有保留的憑證，仍要輸入一次帳密（可用 web 登入頁生物辨識鈕重新開啟）。
- 保留、按登入解鎖、取消後開 web 的原生行為需要 iOS 與 Android 真機驗證。

## 為何難以逆轉

使用者會預期「登出後按登入用 Face ID 就能回來」；改回撤銷又會讓這個行為消失。
