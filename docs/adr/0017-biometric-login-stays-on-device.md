# 生物辨識登入留在本機：不在後端存 passkey，登出後保留受保護的憑證

取代 [ADR-0016](0016-passkey-webauthn-shared-by-api.md)。ADR-0016 要由 api 新增 passkey 憑證儲存，讓 web 與 App 共用；owner 決定不在後端存 passkey，生物辨識只做在 App 端。需求見 trip-planner spec #1683。

ADR-0016 的實作從未合併進 main、沒有部署，`passkey_credentials` 的 migration 也從未在任何環境套用，所以沒有 production 需要還原。

## Decision

- **登出時保留憑證**：已開啟「生物辨識登入」的使用者按「登出」，不清掉受生物辨識保護的 refresh token，也不清掉與它綁定的 DPoP 金鑰；登出不呼叫伺服器端撤銷，否則保留下來的憑證已失效。
- **登入頁入口**：手機上有受保護的憑證時，登入頁提供「用 Face ID／Touch ID 登入」，不必開瀏覽器。入口在憑證被清掉、被伺服器撤銷（refresh 被拒）或生物特徵變更使金鑰失效時消失。
- **「忘記這支手機」**：才真的清掉本機憑證與金鑰，並呼叫伺服器端撤銷。
- **未開啟生物辨識登入的帳號**：登出行為不變，清掉憑證並回到瀏覽器登入。
- **後端不新增任何東西**：沿用現有 refresh token 輪替與撤銷，不新增資料表、端點、環境變數。
- **App 鎖與生物辨識登入維持各自獨立**。

## Considered Options

- **ADR-0016 的 passkey 路線**：web 與 App 共用，換手機也能用。拒絕：要在後端新增憑證儲存與一整組註冊、登入、管理能力，owner 不要後端存這份東西；passkey 綁 RP ID，搬網域會讓全部失效。
- **登出就清掉憑證（現狀）**：簡單、登出後伺服器與手機都乾淨。拒絕：登出後回不來，只能重新輸入密碼，v0.36 登出後按 Face ID 回來的體驗無法恢復。
- **登出讓伺服器端失效、下次仍用 Face ID 免密碼回來**：在不新增後端憑證的前提下做不到，因為免密碼回來必須有一份仍有效的憑證。

## Consequences

- **登出後伺服器端的登入狀態仍然有效**，直到使用者按「忘記這支手機」或從 web 的已登入裝置撤銷。手機遺失時，使用這份憑證仍須通過生物辨識。登出的說明文字必須如實告知這一點。
- **憑證與 DPoP 金鑰必須一起保留、一起刪除**（見 [ADR-0015](0015-dpop-key-bound-tokens.md)）：refresh 必須用同一把金鑰，只留其一，憑證等同作廢。這取代 ADR-0015 生命週期中「登出時與登入憑證一併刪除」的字面規則，改為：開啟生物辨識登入者登出時兩者一併保留；其餘情況（忘記這支手機、關閉生物辨識登入、refresh 被拒、生物辨識失效、帳號刪除）仍一併刪除。
- 登出後重新登入的帳號與保留的帳號不同時，必須先清掉前一個人的憑證，共用手機才不會串帳號。
- 這支手機在 web 的已登入裝置仍會出現，使用者可從那裡撤銷；撤銷後手機端入口於下次 refresh 被拒時消失。
- 保留金鑰與憑證的原生行為無法在自動測試驗證，需要 iOS 與 Android 真機驗證。

## 為何難以逆轉

使用者從此預期「登出後這支手機仍能用 Face ID 回來」，且手機上長期存在一份登出後仍有效的憑證；日後若改回登出即清除，會讓這個行為消失並需要通知使用者。反方向改採後端憑證（如 passkey）則需要新增後端儲存與 RP ID 綁定，同樣不易回頭。
